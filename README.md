# tripa — 文本排版器

一个用 Qt6 写的文本排版小工具：能对文本文件做页面排版、给选中的字随机换字体、
用**自己手写录入的数据**当字体铺到文字上（缺数据会明确警告）、用正则选中文本、
一键选中所有中文 / 英文、把平缓的噪声波叠加到字形笔画上做随机扭曲，以及一键打印。

排版方面还带了：**文字颜色**、**用户自选的随机字体池**、
**仿 Word 的三选项卡段落设置**（缩进/间距、换行/分页、中文版式，带实时预览）。

手写数据的格式直接沿用 [`getpattern`](../getpattern) 项目导出的 CSV，
所以那套手写采集流程不用改，采完把 CSV 丢给 tripa 就能用。

## 1. 编译与运行

需要 Qt 6（Widgets + PrintSupport）和 CMake ≥ 3.16。
本机已验证的配置：Qt 6.11.1 mingw_64 + Qt 自带的 MinGW 13.1 + Ninja。

```powershell
# 让 mingw 和 ninja 在 PATH 里（否则 CMake 找不到编译器/构建器）
$env:PATH = "C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\Ninja;" + $env:PATH

cmake -S . -B build -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_MAKE_PROGRAM="C:/Qt/Tools/Ninja/ninja.exe" `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.11.1/mingw_64" `
  -DCMAKE_C_COMPILER="C:/Qt/Tools/mingw1310_64/bin/gcc.exe" `
  -DCMAKE_CXX_COMPILER="C:/Qt/Tools/mingw1310_64/bin/g++.exe"

cmake --build build
.\build\tripa.exe
```

运行程序时如果提示缺少 DLL，把 `C:\Qt\6.11.1\mingw_64\bin` 和
`C:\Qt\Tools\mingw1310_64\bin` 加进 PATH，或者用 `windeployqt` 打包。

## 2. 功能与用法

### 2.1 页面设置（文件 → 页面设置 / Ctrl+U）

纸张（A4/A5/A3/B5/Letter/Legal/16K/自定义）、纵横方向、
上左下右边距、装订线（附加在左边距上，为装订留白）。
对话框右边是实时预览：纸张比例、正文区域、假文字、装订线一目了然。

编辑区里**整张纸就是白纸黑字**：纸面是白色的，正文写在这张白纸上，
页边距之外是编辑器的深色底（"桌面"），纸张在窗口里横向居中，页与页之间不描边。
所以灰色的部分只是桌面，**不是可以打字的文本框**；
能输入的范围就是白纸里的正文区域。

（注意：白纸黑字是**固定**的，不跟随系统深浅色主题 ——
排版软件不需要"深色纸张"，否则打印预览就没有意义了。）

### 2.2 段落设置（排版 → 段落 / Ctrl+Shift+P）

仿 Word 的三选项卡「段落」对话框，全部映射到 `QTextBlockFormat`：

* **缩进和间距**：对齐方式（左/居中/右/两端/分散）、大纲级别、
  左/右缩进（单位是**字符**，按当前字体折算）、特殊格式（首行缩进 / 悬挂缩进）、
  段前段后（磅）、行距（单倍 / 1.5 倍 / 2 倍 / 固定值 / 多倍 + 设置值）。
* **换行和分页**：段前分页、与下段同页（这两个直接进 `PageBreakFlags`，
  排版引擎会认）；段中不分页、孤行控制在界面里保留但在本程序里只作记录
  —— 分页由 `QTextDocument` 按页面高度自动决定。
* **中文版式**：允许标点溢出边界、允许西文在单词中间换行
  （这个真的生效：切 `QTextOption::WrapMode`）、中文与西文/数字间距、
  按中文习惯控制首尾字符、换行规则。

对话框底部是**真实渲染的预览**：同一段字按当前设置排一遍，
换行、对齐、行距、缩进都能立刻看到，不是示意图。

作用范围：选区覆盖到的所有段落；没有选区就作用于光标所在段落。

### 2.3 文字颜色与其他排版（排版菜单）

* **文字颜色（Ctrl+Shift+C 的位置在工具栏上的色笔图标）**：标准取色对话框，
  作用到选区或"接下来输入的文字"。
* **恢复默认文字颜色**：清掉前景色属性（用 `clearProperty`，
  因为 `mergeCharFormat` 删不掉已存在的属性）。
* 字体下拉框 / 字号：作用于**选中的文字**；没有选区时作用于接下来输入的文字。
* 加粗 / 倾斜 / 下划线：Ctrl+B / Ctrl+I / Ctrl+U。

> 颜色是真正的富文本前景色，而且**手写层和扭曲层会优先采用它**
> —— 上过色的字，扭曲后依然是那个颜色，不再是一片蓝。

### 2.4 随机字体（排版菜单 / Ctrl+R）

* **选择随机字体池（排版 → 选择随机字体池）**：勾出允许随机的字体，
  带过滤器、全选 / 全不选 / 恢复推荐集合三个按钮。
  **随机只会在这个集合里发生**，不会再"从系统里所有字体里乱抽"
  （那样抽出来的字体可能根本没法读）。字体池存在 `QSettings` 里，下次打开还在。
* **给选中文字随机设置字体（Ctrl+R）**：选区内每个字随机换一个**字体池里**的字体，
  并可在工具栏「随机字号」两个框里设定随机字号区间
  （最小值 = 最大值时只随机字体、不随机字号）。没选文字会明确提示，不会偷偷作用到全文。
* **取消选中文字的随机字体**：回到文档的全局字体。

### 2.5 手写数据当字体用（手写菜单）

手写笔迹来自 `getpattern` 导出的 CSV，一个 CSV 就是一个（或几个）手写字符。
程序启动时会自动加载：

1. 内置数据 `qrc:/handwrite`（仓库里 `handwrite/*.csv`，示例字母 a–z）；
2. 程序目录下的 `handwrite/`、`patterns/`；
3. `getpattern` 的 UWP 数据目录（如果存在）。

要换成自己的字迹：**手写 → 载入手写数据（CSV 目录）**，选一个放 CSV 的目录即可
（同一个字符可以放多份 CSV，程序会随机取用其中一份，字迹就不会千篇一律）。

用法：

1. 选中要变手写的文字（可以用「选中 → 一键选中所有中文 / 英文」或正则选）；
2. **手写 → 把手写数据铺到选中文字上（Ctrl+H）**；
3. 显示方式自动切到「显示手写效果」；工具栏「手写遮住正文」勾上后笔迹会盖住原字。

**找不到数据时会明确警告**，而且不止一处：

* 铺手写前，先列出选区里**每一个缺数据的字符**，问你要不要继续（继续的话这些字保持原字体）；
* 铺完之后，状态栏再报一次**全文**缺数据的字符；
* **手写 → 查看手写数据（校对表）**：表格列出库里每个字符的预览图、样本数、笔画数、
  点数、来源 CSV，缺数据的字符会红字列在最后 —— 一眼就能看出还差哪些字要采。

> 提示：手写数据只覆盖文档里真正有笔迹的那一层，**不会改动字符本身**，
> 所以正则、选中、复制、保存都照常工作。

### 2.4 正则表达式选中文本（选中菜单 / Ctrl+F）

工具栏第二行的「正则:」框里写表达式，回车或点「选中」：

* 匹配到的部分会被**选中**（主选区是第一个匹配，方便直接接着操作）；
* 其余匹配用**黄色高亮**标出来，一眼能看到一共命中多少处；
* 之后的字体 / 手写 / 扭曲操作会作用于**全部匹配**（不止第一个），
  状态栏会显示「正则命中 N 处」。

例子：`[0-9]{4}` 选中所有四位数字、`[，。、]` 选中所有标点、`\s{2,}` 找多余空格。
文档内容一改，匹配区间就自动失效，不会作用到错位置。

### 2.5 一键选中所有中文 / 英文（Ctrl+1 / Ctrl+2）

按 Unicode Script 判断：`Ctrl+1` 选中文（汉字，含扩展区），`Ctrl+2` 选英文（拉丁字母）。
空格算作通过，标点/数字算作分界。

实现上取的是**从起点开始最长的一段连续同类文本块**（英文/中文连续段可含空格，
数字和标点会截断），状态栏会告诉你选中了多少字、跳过了多少个异类字符。
若一开始就没有选区，则从文档开头开始选；如果已经选中了某一段，则从该段起点开始找。

之所以是"一块"而不是字面意义的"全部"：Qt 的 `QTextCursor` 只支持一段连续选区，
做不到多段选中的原生表示。想要真正的中英混排全选效果，
用正则 `[\p{Script=Han}]` / `[A-Za-z]` 选（同样只落在第一个匹配上，
但**其余匹配会黄色高亮、并且效果操作会作用于全部匹配**，见 2.4）。

### 2.8 笔画随机扭曲（效果菜单 / Ctrl+D）

原理就是题目说的：**把一条平缓的噪声波 add 到字形路径上**。

* `NoiseWave`：3 个随机相位、随机频率的正弦波叠加再归一化。
  单个正弦本身是平缓的，叠加起来既平滑又"随机"；同一个 seed 波形完全可复现。
* 变形本身用的是**平滑二维位移场** `d(x, y)`，不是"沿法线推"：

  ```
  dx = 0.62·sin(2πf·u + φx) + 0.38·sin(2πf·v + φc)
  dy = 0.62·sin(2πf·v + φy) + 0.38·sin(2πf·u + φc)
  ```

  位移是位置的连续函数，所以相邻点位移几乎相同，笔画之间的相对关系不会断裂。
  减去字形中心处的值，整个字不会被平移，基线和字宽保持稳定。
* **幅度安全上限**：取"不同轮廓之间的最小距离 × 0.45"。
  位移最多把任意两点拉近 `2×幅度`，所以只要幅度小于这个上限，
  轮廓之间就不可能相交，映射保持单射 —— **字形有几个洞就还是几个洞**。
  这个上限是必需的：一个 40pt 的 `0`，包围盒 26×41，可笔画只有 2.3pt 宽，
  按包围盒给上限（12pt）足以把洞整个推穿，填充出来就是一团实心块。
  想要更夸张的抖动可以往大调幅度，超了会自动钳住。
* **波数**：横竖方向各走几个噪声周期，默认 2（就是"平缓的波"）。
* **扭曲替换正文**（工具栏复选框，默认勾选）：勾上时先把这一格刷成纸色、
  再画扭曲后的字形，于是屏幕上什么样、纸上/PDF 里就什么样，
  不会"导出后还留着原字体"。取消勾选就变成半透明叠加，方便对照改了哪些笔画。
* **扭曲选中文字的笔画（Ctrl+D）**：给每个字符一个独立的随机种子
  （所以每个字扭曲得都不一样）。
* **换一条噪声波并重新扭曲**：只换波形重新扭，得到另一种抖动。

固定手写字形同样吃这套扭曲（手写层也会按同一个噪声波抖）。

### 2.7 打印与导出

* **文件 → 打印（Ctrl+P）**：标准打印对话框，正文 + 手写 + 扭曲一起输出。
* **文件 → 导出 PDF**：同样的渲染逻辑，方便先看效果。
* 打印时以**打印机实际纸张**为准（可能和页面设置不同），边距沿用页面设置。

> **打印子系统的连接只发生在你按下「打印」之后。**
> 程序启动、打开文件、页面设置、导出 PDF 都不会去连打印机。
> 这一点很关键：Windows 上 `QPrinter` 一被构造出来就会去 `CreateDC`
> 连系统默认打印机，如果默认打印机是网络/WSD 打印机且当前不可达，
> 这个调用会卡住好几秒并弹出系统的「请等待打印机连接或取消连接」。
> 所以：
>
> * 导出 PDF 走 `QPdfWriter`，**完全不碰**打印子系统；
> * `QPrinter` 只在 `printDocument()` 里构造，也就是用户确认打印那一步。
>
> 如果你自己也遇到这个系统弹窗，另一个有效的做法是把
> **Windows 默认打印机改成 `Microsoft Print to PDF` 之类的本地打印机**——
> 打印对话框一打开列的就是它，不会去连接那台网络打印机。

### 2.8 打开 / 保存

* 打开：UTF-8 文本（.txt/.md/.csv/.log 或任意文件）。
* 保存：另存为 UTF-8 文本，**只保存文字本身**。
  （字体、手写、扭曲这些效果不写进 txt —— 目前没有存效果的文件格式，
  需要的话可以再加 JSON/HTML 导出。）

## 3. 手写数据（pattern）格式

和 `getpattern` 的导出**完全一致**：

```
a                       <- 第 1 行：字符标签（这一个文件里的笔画写的是什么字）
560,2030,0.7            <- 之后每行：x,y,pressure
558.6,2030,0.7
                        <- 1 个空行 = 笔画边界（一笔结束）
560,2030,0.7
560,2600,0.7
```

约定：

* 标签是**一个**字符 → 文件里所有笔画都属于它；
* 标签是**多个**字符（如 `abc`）且笔画数正好等于字符数 → 一笔一个字；
* 标签是多字符但笔画数更多 → 按 x 方向间隙把笔画切成对应份数
  （取最大的 n−1 个间隙当切分点）；
* 坐标原点无所谓：加载时会把每个字的包围盒归一化到左上角 (0,0)，
  渲染时按目标字高等比缩放（保留采集时的宽高比）。

`handwrite/` 里的 a–z 是 `tools/make_sample_pattern.py` 生成的示例字母，
保证程序装上就有东西可看。要换成真手写体，直接用自己的 CSV 覆盖或另放目录。

其它工具：

```powershell
python tools\make_sample_pattern.py   # 重新生成示例字母 CSV
python tools\make_icon.py             # 重新生成程序图标
```

## 5. 实现要点

代码结构（每个文件都不大，方便按需改）：

| 文件 | 作用 |
| --- | --- |
| `mainwindow.*` | 菜单、工具栏、所有动作的编排 |
| `texteditor.*` | 所见即所得的编辑区：文档分页 + 自绘纸张/阴影 + 唯一的坐标变换 |
| `effectsoverlay.*` | 盖在 viewport 上的透明层，只画手写/扭曲 |
| `effectsrenderer.*` | 手写笔迹与扭曲字形的实际绘制（屏幕/打印/PDF 共用） |
| `noise.*` | 平缓噪声波、重采样、平滑、按法线扭曲折线（手写层用） |
| `handwriting.*` | CSV 解析、按间隙切字、归一化、多样本随机取用 |
| `effect.*` | 字符级效果（存进 `QTextCharFormat` 的自定义属性） |
| `pagesetup.*` | 页面设置数据结构 + 带预览的对话框 |
| `paragraph.*` | 段落格式（缩进/间距/换行分页/中文版式）+ Word 风格对话框 |
| `fontspool.*` | 随机字体池的选择对话框与持久化 |
| `proofsheet.*` | 手写数据校对表（含缺字清单） |
| `main.cpp` | 程序入口 + 统一的分页渲染（PNG/PDF/打印共用）+ 自检入口 |

几个关键取舍：

* **效果不改字符，只改"怎么画"**。手写和扭曲都存在 `QTextCharFormat` 的自定义属性里
  （`EffectKind` + `seed`），文档里始终是原来的字符，因此正则/选中/复制/保存都不受影响。
  想改回普通文字，清掉属性即可（`清除选中文字的全部效果`）。
* **手写/扭曲画在覆盖层上**，不参与 `QTextDocument` 的排版，
  所以不会因为"换了字体"而让断行位置乱跳；打印时用同一套绘制代码叠在正文上，
  真正做到所见即所得。
* **同一个 seed 永远得到同一份样本、同一条波形**，因此重绘、缩放、
  打印都不会让字迹"跳来跳去"；点「换一条噪声波」才会变。
* 字形轮廓由 `QPainterPath::addText()` 取到，自己按容差**自适应细分**曲线
  （Qt6 的 `toSubpathPolygons()` 没有容差参数，内部固定按比较粗的步长细分，
  长笔画会被整段直线化，噪声一叠字形就散了了）。
* **打印子系统是惰性的**：`QPrinter` 只在 `MainWindow::printDocument()` 里构造，
  导出 PDF 用 `QPdfWriter`，`PageSetup::pageSize()` 用"值对象"构造（只查 Qt 静态纸张库）。
  加新功能时请守住这条：任何地方都不要在用户点「打印」之前构造 `QPrinter`
  或查询 `QPrinterInfo`，否则网络打印机不可达时会卡住启动/操作并弹系统连接提示。

### 版面坐标系统的六条铁律

覆盖层（手写/扭曲）必须和正文**逐像素重合**，光标/选区要画在对的位置，
鼠标也必须点得准。为此有六个容易踩的坑，都在 `texteditor.*`
和 `effectsrenderer.cpp` 里标注了，改动时别破坏：

1. **换行宽度必须显式钉在正文宽度上。**
   `QTextEdit` 默认的 `LineWrapMode::WidgetWidth` 会**忽略** `document()->pageSize()`，
   直接按 viewport 宽度断行。纸张居中后 viewport 比正文区宽得多，
   于是断行位置和打印结果不一致。所以 `applyLayoutMetrics()` 里两件事一起做：
   `document()->setPageSize(正文尺寸)` + `setLineWrapColumnOrWidth(正文宽度)`。

2. **纸张居中量只能由"编辑区宽度"算，绝不能读 `viewport()->width()`。**
   居中量是拿去做 `setViewportMargins(pad, 0, 0, 0)` 的，于是
   "边距缩窄 viewport、viewport 宽度又决定居中量"会形成 105/106
   来回震荡的无限递归，直到栈溢出（踩过）。
   `paperPadPx()` 用 `width() - 滚动条预留` 算，与当前状态无关。

   > 注意：这个量**已经体现在 viewport 原点的 x 上**了
   > （viewport 左边缘就是纸张左边缘），所以画纸时不能再加一次。
   > 曾经加过，纸被推右 76 像素，光标就再也落不到纸面上。

3. **有三个坐标空间，别混：文档坐标 / 排版坐标 / viewport 局部坐标。**

   | 空间 | 原点 | 值域来源 |
   |---|---|---|
   | 文档坐标 | 第一页正文区左上角 | `documentLayout()->blockBoundingRect()` |
   | 排版坐标 | 第一页**纸张**左上角 | `documentToViewport()` 的值域 |
   | viewport 局部坐标 | viewport 左上角 | `QMouseEvent::pos()`、`QPainter(viewport())` |

   换算关系：`排版坐标 = 文档坐标 + 正文区原点(bodyOriginPx)`；
   `viewport 局部坐标 = 排版坐标 - viewportOriginInEditor()`。
   正文、光标、选区、效果覆盖层一律用 `documentToViewport()`；
   鼠标进来先 `viewportToEditor()`，再 `documentCursorAt()`。

4. **正文、光标、选区、覆盖层必须共用同一个原点变换**，也就是
   `TextEditor::documentToViewport()`。任何一边自己 `translate`
   都会让笔迹或光标整体偏一个页边距。

5. **`QPainterPath::addText()` 的坐标：y 向下、基线在原点、单位是磅。**
   一个 18pt 的 `l` 轮廓是 `(x, 0) .. (x, 15.2)`，`0` 就是基线。
   所以：不要乘 1/64 的"定点转换"（整体缩小 64 倍），
   也不要再翻一次 y（字会上下颠倒、还会被挪到基线下面去）。
   这两件事以前都干过，`--uitest` 里的 `uitest_outline_orient.png`
   就是专门用来核对这一条的（`L`/`F` 上下不对称，被镜像了一眼就能看出）。

6. **求"这个字用什么字体"不能用 `QTextCharFormat::font()`。**
   它只返回格式里**显式设过**的属性，没设的字号会落到 `QFont` 的默认值
   （→ QApplication 的默认字号），而**不是**文档的默认字体。
   文档里只有一部分字显式设过字号时（"整篇 28pt、其中几个字被单独改过"），
   拿它算出来的"行高 / 自然字高"比例会差一倍，笔迹要么缩成一半、要么涨成两倍。
   统一走 `effectiveFont()`（默认字体 → 块格式 → 片段格式逐层 `resolve`）。

### 光标和选区为什么要自己画

`TextEditor` 的 `paintEvent` 是自己写的（要画纸张、页边距、居中），
于是绕开了 `QTextEdit` / `QWidgetTextControl` 里那两条默认通路：

* **光标**：`PaintContext::cursorPosition` 默认是 `-1`（= 不画），
  而"此刻该不该显示"（闪烁相位）是 `QWidgetTextControl` 的私有状态，
  外人拿不到。所以光标由 `drawCaret()` 自己画：
  位置取 `QTextEdit::cursorRect()`（**文档坐标**）+ `documentOriginInViewport()`，
  闪烁沿用 Qt 自带定时器的相位（它在暗相位会把 `cursorRect()` 置空）。
* **选区**：默认是在 `QWidgetTextControl::drawContents()` 里把选区塞进
  `PaintContext::selections` 的。这里没走那条路，所以要自己填
  `context.selections`，颜色取调色板里的 `Highlight` / `HighlightedText`
  （深色主题默认给的浅色前景落到白纸上就等于隐形）。
* **鼠标**：`QTextEdit::cursorForPosition()` 内部按自己那套换算
  （viewport 边距、行高取法都和这里不一样），和正文实际画的位置差一个页边距。
  三个鼠标事件都重写了，统一走 `documentCursorAt()`。

### 自检怎么量"对齐"

`--uitest <目录> dark|light probe` 不只是截图，它会：

* 强制一套深色/浅色调色板，断言**纸面是白的、字是深色的**
  （深色主题曾经把纸张涂成灰色、文字看不见）；
* **光标**：在**空文档**下截图（此时画面上除了光标什么都没有，
  不用再猜"这团墨迹是字母还是光标"——`I`、`H` 的竖笔也是整行高），
  量出竖条的位置，断言它与 `documentOriginInViewport() + cursorRect()`
  的偏差在 3 像素内，而且落在纸面里（跑到灰桌面上就是"看不见"）；
* **选区**：全选后断言高亮左边缘 = 正文左边缘、右边缘不超出纸张
  （颜色只认钉死的 `#3399ff`，否则窗口描边、面板拖柄会被算进来）；
* **鼠标定位**：在第 0/1/2 行各点一下，断言光标确实落在那一行；
* **精确拖选**：从第 0 个字拖到第 5 个字，断言正好选中 `HANDW`
  （只断言行号不够 —— "框选不到想要的位置"恰恰是列的问题）；
* **Shift+方向键**：扩选 4 次，断言选中 `HAND` 且画面上真有高亮像素
  （用户报过"Shift 扩选有效但看不到提示"）；
* **效果层对齐**：把正文和覆盖层各画一遍到同尺寸画布，
  比较两者墨迹的包围盒，超阈值就报错退出；
  同时按行高分段统计墨迹，区分"整体平移"和"某几行被缩放"；
* **字形拓扑**：对 `0 4 扭 H g 回 %` 断言变形前后**每条轮廓的绕向不变**
  —— 有符号面积一旦翻号，"洞"就会被填实（`0` 变实心椭圆）；
* 输出几张给人看的对照图：`uitest_cursor_zoom.png`（光标附近放大）、
  `uitest_glyph_compare.png`（原字形 vs 扭曲后）、
  `uitest_align_check.png`（正文与扭曲字形共基线）、
  `uitest_iso_effect.png`（正文 + 暗红扭曲层叠在一起）、
  `uitest_outline_orient.png`（方位核对）。

> 量测的坑：`QWidget::grab()` 对**子控件**是把控件画在**父控件坐标系**里再截的，
> 不是控件局部坐标。曾经拿 viewport 的 grab 当"viewport 内的位置"用，
> 整段测量凭空平移了一个纸张居中量，于是得出了错的结论。
> 现在统一在**窗口坐标**里量，并且扫描范围卡在纸面以内
> （紧挨着纸右边的竖滚动条是整条深色，扫进去会把包围盒拉歪）。

## 6. 已知限制

* 保存只写纯文本，效果（手写/扭曲）不落盘，重开需要重新应用。
* 内置示例手写数据只有 a–z（几何字母造型，不是真人笔迹）；
  中文、数字、标点需要自己采（校对表会告诉你缺哪些）。
* 精确的一键"选中所有"在 Qt 里做不了：`QTextCursor` 只支持一段连续选区。
  所以这里取"最长连续同类块 + 黄色高亮其余匹配"，并且让效果操作作用于全部匹配。
* 手写层与扭曲层是"覆盖绘制"，不改变文档排版；
  如果希望手写字**参与排版**（按笔迹宽度重新断行），需要把手写做成真正的 QFont，
  那是另一条路线（可以再谈）。
