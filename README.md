# tripa — 文本排版器

一个用 Qt6 写的文本排版小工具：能对文本文件做页面排版、给选中的字随机换字体、
用**自己手写录入的数据**当字体铺到文字上（缺数据会明确警告）、用正则选中文本、
一键选中所有中文 / 英文、把平缓的噪声波叠加到字形笔画上做随机扭曲
（**已经有手写的字就把噪声加到笔迹上**），以及一键打印、Ctrl+滚轮缩放。

排版方面还带了：**文字颜色**、**用户自选的随机字体池**、
**仿 Word 的三选项卡段落设置**（缩进/间距、换行/分页、中文版式，带实时预览）。

手写数据的格式直接沿用 [`getpattern`](../getpattern) 项目导出的 CSV，
所以那套手写采集流程不用改，采完把 CSV 丢给 tripa 就能用。

## 1. 编译与运行

需要 Qt 6（Widgets + PrintSupport）和 CMake ≥ 3.16。
本机已验证的配置：Qt 6.11.1 mingw_64 + Qt 自带的 MinGW 13.1 + Ninja。

```powershell
# 让 mingw 和 ninja 在 PATH 里（否则 CMake 找不到编译器/构建器）
$env:PATH = "C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\Ninja;" + $env:PATH

cmake -S . -B build -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_MAKE_PROGRAM="C:/Qt/Tools/Ninja/ninja.exe" `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.11.1/mingw_64" `
  -DCMAKE_C_COMPILER="C:/Qt/Tools/mingw1310_64/bin/gcc.exe" `
  -DCMAKE_CXX_COMPILER="C:/Qt/Tools/mingw1310_64/bin/g++.exe"

cmake --build build
.\build\tripa.exe
```

运行程序时如果提示缺少 DLL，把 `C:\Qt\6.11.1\mingw_64\bin` 和
`C:\Qt\Tools\mingw1310_64\bin` 加进 PATH，或者用 `windeployqt` 打包。

### 出问题了怎么查：日志与崩溃报告

程序自带一套日志（`tripalog.*`），**默认就开着**，什么都不用配：

```powershell
# 界面上：帮助 → 复制诊断信息   （把日志尾部+环境信息放进剪贴板，直接贴回来）
#         帮助 → 打开日志文件
# 命令行（现场排查时用这个：日志更详细）
.\build\tripa.exe --log=debug                 # Info 以上 + 分页/几何/缩放细节
.\build\tripa.exe --log=trace                 # 再加上每一次绘制（很啰嗦，只在必要时开）
.\build\tripa.exe --log=debug --log-file=D:\tripa.log   # 换日志位置
.\build\tripa.exe --no-log                    # 关掉日志（只留崩溃报告）
```

| 东西 | 默认位置 |
| --- | --- |
| 日志 | `%LOCALAPPDATA%\tripa\tripa.log`（超过 4 MB 轮转到 `tripa.log.1`） |
| 崩溃报告 | `%LOCALAPPDATA%\tripa\tripa-crash-<时间>.txt` |

日志长这样（左边是时间、进程启动到现在的毫秒数、行号；然后是级别、线程、类别）：

```
14:22:31.508 +   4370ms #    60 [DEBUG] [Qt mainThread] [layout] 滚动范围 0 -> 98（文档高=312.0 页数=1 纸高=1122.5 缩放=2.000 视口高=602）  (updateScrollRange:498)
14:22:31.520 +   4382ms #    61 [INFO ] [Qt mainThread] [zoom] 缩放 100% -> 200%（纸 1587.4x2245.0 视图像素，锚点 400,300，滚动 0/331）  (applyZoom:590)
```

* 级别：`--log`（=Info）记"用户看得懂的动作"（开/存/缩放/改页面设置），
  `--log=debug` 加"排查用的细节"（分页几何、重排、滚动范围、绘制摘要），
  `--log=trace` 再加"每一次绘制"和每个页面的窗口范围。
* **Qt 自己的 `qDebug/qWarning` 也进同一个文件** —— Qt 报的
  "Painter not active"、"Position out of range" 之类经常直接指出问题。
* **崩溃报告**（`tripa-crash-*.txt`）不用开日志也有：异常码、出错地址、
  出错模块、CPU 寄存器、**崩溃前最后那条面包屑**（"当时正在画第几页"）、
  文档快照、以及**最后 400 条日志**。写报告用的是 tryLock + 裸 fwrite，
  绝不在这里死等锁或分配内存 —— 崩溃时"程序卡住写不出报告"比崩溃还糟。
* 这套东西是能自证的：`--uitest <目录> light crashtest` 会**故意崩一个子进程**，
  然后检查 dump 里八项内容（异常码、面包屑、日志、寄存器、模块…）齐不齐。
  崩溃处理这条路"平时不走"，不主动测就等于没写。

**它是怎么被用上的**（这两个真实缺陷都是日志抓出来的，值得当例子）：

1. **一秒 3704 次 `updateScrollRange`（界面直接卡死）**：
   日志里 `updateScrollRange` 每秒冒出几千行，一看就知道是活锁。
   加上"是谁调进来的"之后定位到 `resizeEvent`；再加一行 resize 日志，
   看到**宽度在 1110 <-> 1096 之间来回跳** —— 竖滚动条反复显隐（差 14 像素），
   每跳一次都重排 + 重绘。修法：`setVerticalScrollBarPolicy(AlwaysOn)`，
   再把版面回调从"直接相连"改成"排到下一轮并合并重复请求"。
2. **"第一页打字、第二页出现同样的字"**：
   日志里每页的"正文窗口（文档坐标）"范围一眼能看出来 ——
   正常应当是第 1 页 `0..971`、第 2 页 `1122..2094`；
   出问题时两页会**落在一起**，或者第 2 页的窗口落在文档开头。
   `pagefix` 自检现在还会直接量**两张纸之间那道缝**里有没有墨（见下）。

## 2. 功能与用法

### 2.1 页面设置（文件 → 页面设置 / Ctrl+U）

纸张（A4/A5/A3/B5/Letter/Legal/16K/自定义）、纵横方向、
上左下右边距、装订线（附加在左边距上，为装订留白）、
**页眉页脚**（默认两个都不显示；勾上之后写文字，里面可以用 `{page}` /
`{pages}` / `{title}`，字号也能调）。
对话框右边是实时预览：纸张比例、正文区域、假文字、装订线、页眉页脚一目了然。

> 页眉画在上边距里、页脚画在下边距里，**占不到正文窗口** ——
> 所以开不开页眉页脚都不会让文字重排（断行位置、页数一个都不变）。
> 页眉页脚会跟着 `.tripa` 一起存（见 2.9），不放心的可以关掉再存。
编辑区里**整张纸就是白纸黑字**：纸面是白色的，正文写在这张白纸上，
页边距之外是编辑器的深色底（"桌面"），纸张在窗口里横向居中，页与页之间不描边。
所以灰色的部分只是桌面，**不是可以打字的文本框**；
能输入的范围就是白纸里的正文区域。

> 桌面在纸的左右两侧必须是**同一个颜色**。纸张居中量是做成 viewport 左边距的
> （见第 5 节的铁律 2），于是纸左边那条留白属于**控件自己的背景**、右边那条才是
> 编辑区画出来的 —— 两边各刷各的就会一深一浅（右边更浅，很容易看出来）。
> 修法是让控件自己的背景画刷也用桌面色（`setAutoFillBackground` + 调色板），
> 因为 `paintEvent` 拿到的是 **viewport 的**绘制事件（实测事件矩形正好等于
> viewport 尺寸，而控件比它宽一个居中量），控件自己那条边在 `paintEvent` 里刷不到。

（注意：白纸黑字是**固定**的，不跟随系统深浅色主题 ——
排版软件不需要"深色纸张"，否则打印预览就没有意义了。）

### 2.2 段落设置（排版 → 段落 / Ctrl+Shift+P）

仿 Word 的三选项卡「段落」对话框，全部映射到 `QTextBlockFormat`：

* **缩进和间距**：对齐方式（左/居中/右/两端/分散）、大纲级别、
  左/右缩进（单位是**字符**，按当前字体折算）、特殊格式（首行缩进 / 悬挂缩进）、
  段前段后（磅）、行距（单倍 / 1.5 倍 / 2 倍 / 固定值 / 多倍 + 设置值）。
* **换行和分页**：段前分页、与下段同页（这两个直接进 `PageBreakFlags`，
  排版引擎会认）；段中不分页、孤行控制在界面里保留但在本程序里只作记录
  —— 分页由 `QTextDocument` 按页面高度自动决定。
* **中文版式**：允许标点溢出边界、允许西文在单词中间换行
  （这个真的生效：切 `QTextOption::WrapMode`）、中文与西文/数字间距、
  按中文习惯控制首尾字符、换行规则。

对话框底部是**真实渲染的预览**：同一段字按当前设置排一遍，
换行、对齐、行距、缩进都能立刻看到，不是示意图。

作用范围：选区覆盖到的所有段落；没有选区就作用于光标所在段落。

### 2.3 文字颜色与其他排版（排版菜单）

* **文字颜色（Ctrl+Shift+C 的位置在工具栏上的色笔图标）**：标准取色对话框，
  作用到选区或"接下来输入的文字"。
* **恢复默认文字颜色**：清掉前景色属性（用 `clearProperty`，
  因为 `mergeCharFormat` 删不掉已存在的属性）。
* 字体下拉框 / 字号：作用于**选中的文字**；没有选区时作用于接下来输入的文字。
* 加粗 / 倾斜 / 下划线：Ctrl+B / Ctrl+I / Ctrl+U。

> 颜色是真正的富文本前景色，而且**手写层和扭曲层会优先采用它**
> —— 上过色的字，扭曲后依然是那个颜色，不再是一片蓝。

### 2.4 随机字体（排版菜单 / Ctrl+R）

* **选择随机字体池（排版 → 选择随机字体池）**：勾出允许随机的字体，
  带过滤器、全选 / 全不选 / 恢复推荐集合三个按钮。
  **随机只会在这个集合里发生**，不会再"从系统里所有字体里乱抽"
  （那样抽出来的字体可能根本没法读）。字体池存在 `QSettings` 里，下次打开还在。
* **给选中文字随机设置字体（Ctrl+R）**：选区内每个字随机换一个**字体池里**的字体，
  并可在工具栏「随机字号」两个框里设定随机字号区间
  （最小值 = 最大值时只随机字体、不随机字号）。没选文字会明确提示，不会偷偷作用到全文。
* **取消选中文字的随机字体**：回到文档的全局字体。

### 2.5 手写数据当字体用（手写菜单）

手写笔迹来自 `getpattern` 导出的 CSV，一个 CSV 就是一个（或几个）手写字符。
程序启动时会自动加载：

1. 内置数据 `qrc:/handwrite`（仓库里 `handwrite/*.csv`，示例字母 a–z）；
2. 程序目录下的 `handwrite/`、`patterns/`；
3. `getpattern` 的 UWP 数据目录（如果存在）。

要换成自己的字迹：**手写 → 载入手写数据（CSV 目录）**，选一个放 CSV 的目录即可
（同一个字符可以放多份 CSV，程序会随机取用其中一份，字迹就不会千篇一律）。
选的目录会**递归**搜索子文件夹 —— `patterns/alice/`、`patterns/2024-05-01/` 这种
按人/按次分层的导出目录，直接选最外层就行。

用法：

1. 选中要变手写的文字（可以用「选中 → 一键选中所有中文 / 英文」或正则选）；
2. **手写 → 把手写数据铺到选中文字上（Ctrl+H）**；
3. 显示方式自动切到「显示手写效果」；工具栏「手写遮住正文」**默认勾上** ——
   笔迹直接顶替机打字（原字不画，屏幕上和导出/打印结果一致）；
   取消勾选才变成半透明叠加，用来对照哪些字铺上了手写。

工具栏的「**笔宽**」是笔压换算成笔画粗细的系数：**线宽 = 该点笔压 × 字号 × 系数**
（默认 0.20，即笔压 1.0 时线条有字号的 20% 粗，接近钢笔手感）。
不同采集程序导出的 depth 量级差别很大（getpattern 实测中位数 0.25、峰值 0.8），
觉得太粗/太细就拖这个旋钮，调 0 则忽略笔压、按字高的固定比例画。

**一个 CSV 里有多个字时怎么切**（按可靠性排序）：

1. CSV 自带的字符边界（**2 个空行 = 字符边界**，getpattern 就是这么导出的）直接用；
2. 边界数对不上标签字数时，先按几何修：丢掉抬笔跨页的连线（大得不像一个字）、
   按阅读顺序重排（书写顺序 ≠ 阅读顺序）、组多了合并最像"同一个字被切开"的一对、
   组少了按组内 x 空档切开过宽的组；
3. 还不行才退回"按 x 间隙猜字"的老办法。

> 踩过的坑：早期版本把所有空行一视同仁，边界信息全丢，多字符文件一律靠猜 ——
> 一行写不下、折行写的文件必然张冠李戴（实测一个「好」只分到 2 笔，这字要 5~6 笔，
> 画出来是一团认不出的墨）。

**找不到数据时会明确警告**，而且不止一处：

* 铺手写前，先列出选区里**每一个缺数据的字符**，问你要不要继续（继续的话这些字保持原字体）；
* 铺完之后，状态栏再报一次**全文**缺数据的字符；
* **手写 → 查看手写数据（校对表）**：表格列出库里每个字符的预览图、样本数、笔画数、
  点数、来源 CSV，缺数据的字符会红字列在最后 —— 一眼就能看出还差哪些字要采。

> 提示：手写数据只覆盖文档里真正有笔迹的那一层，**不会改动字符本身**，
> 所以正则、选中、复制、保存都照常工作。

> 手写和扭曲**可以叠在同一个字上**：先 Ctrl+H 铺手写、再 Ctrl+D 加噪声，
> 噪声是加到笔迹上的（字还是手写体，只是抖起来）。
> 见 2.8 里那张表 —— 已经有手写的字，套扭曲不会再换回机打字。

#### 基线 / 大小逐字校正（手写 → 调整手写基线 / 大小…）

手写样本的包围盒**底边**默认就压在基线上，但有两类字会因此不对：

* 带下伸部的字（g/y/p/q/j）：墨迹本该沉到基线以下，默认却整字偏高；
* 采集时混进了抬笔连线、或者笔画被切错的样本：包围盒虚高，按"塞满字身框"
  的规则缩放后整字偏小。

这两件事都没法从数据本身推出来，只能人对着参考字形看一眼、拖两下。
对话框按 **CSV 文件**列表（校正文件就是按文件存的），每个字符一行：

| 列 | 含义 |
| --- | --- |
| 序号 / 字 | 字符在 CSV 标签里的位置（xml 里的 `index` 从 0 起） |
| 预览 | 字格（点线）+ 基线（虚线）+ 参考字形（当前工具栏字体，浅灰）+ 手写笔迹（蓝） |
| 基线 % | 相对**字身高**（行内 ascent+descent）的偏移，正数 = 往下沉 |
| 大小 % | 字形缩放倍率，100% = 默认的"等比塞满字身框" |
| 笔画 / 点 | 该样本的笔画数与点数（切错的样本一眼能看出来） |

* 「**自动对齐（选中行 / 本文件全部）**」：按参考字形**墨迹轮廓**（`QPainterPath`
  的紧包围盒，汉字也能正确回退到实际字体）算出基线和大小 ——
  就是把"手写体和机打体一样大、底边落在同一个地方"这件事一次做完；
  算出来太离谱的样本（只有一个点、比例夸张）会**原样留着**，不硬改。
* 「**恢复默认**」：回到"底边压基线、塞满字身框"。
* 调过的行会刷一层浅黄，一屏几十个字也能扫出改过哪些。

校正值存在**与 CSV 同名的 xml** 里（`handwrite23.csv` → `handwrite23.xml`），
载入 CSV 时自动读回 —— 调一次，以后一直生效：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<tripaHandwriting version="1" csv="handwrite23.csv">
    <!-- baseline 单位 = 字身高的比例，正值往下沉；index 是字符在标签里的下标（0 起） -->
    <char index="37" label="好" baseline="0.0310" size="0.8820"/>
</tripaHandwriting>
```

* 关窗口就落盘（点 X、按 Esc、点「保存并关闭」都走同一条路）；
* 写盘用 `QSaveFile` 原子写，写一半被打断不会留下半截 xml；
* 没调过的 CSV **不会**凭空多出 xml；把某个字改回默认，xml 里那一条会被抹掉；
* 内置数据（`qrc:/handwrite`）是只读的：能调、能看效果，但保存时会明确告诉你存不下来。

> 校对表的预览也按校正后的效果绘制，并在摘要里写明"其中 N 个字符带校正"——
> 不然看到某个字比记忆里小一圈，会以为是数据坏了。

### 2.4 正则表达式选中文本（选中菜单 / Ctrl+F）

工具栏第二行的「正则:」框里写表达式，回车或点「选中」：

* 匹配到的部分会被**选中**（主选区是第一个匹配，方便直接接着操作）；
* 其余匹配用**黄色高亮**标出来，一眼能看到一共命中多少处；
* 之后的字体 / 手写 / 扭曲操作会作用于**全部匹配**（不止第一个），
  状态栏会显示「正则命中 N 处」。

例子：`[0-9]{4}` 选中所有四位数字、`[，。、]` 选中所有标点、`\s{2,}` 找多余空格。
文档内容一改，匹配区间就自动失效，不会作用到错位置。

### 2.5 一键选中所有中文 / 英文（Ctrl+1 / Ctrl+2）

按 Unicode Script 判断：`Ctrl+1` 选中文（汉字，含扩展区），`Ctrl+2` 选英文（拉丁字母）。
空格算作通过，标点/数字算作分界。

实现上取的是**从起点开始最长的一段连续同类文本块**（英文/中文连续段可含空格，
数字和标点会截断），状态栏会告诉你选中了多少字、跳过了多少个异类字符。
若一开始就没有选区，则从文档开头开始选；如果已经选中了某一段，则从该段起点开始找。

之所以是"一块"而不是字面意义的"全部"：Qt 的 `QTextCursor` 只支持一段连续选区，
做不到多段选中的原生表示。想要真正的中英混排全选效果，
用正则 `[\p{Script=Han}]` / `[A-Za-z]` 选（同样只落在第一个匹配上，
但**其余匹配会黄色高亮、并且效果操作会作用于全部匹配**，见 2.4）。

### 2.8 笔画随机扭曲（效果菜单 / Ctrl+D）

原理就是题目说的：**把一条平缓的噪声波 add 到字形路径上**。

* `NoiseWave`：3 个随机相位、随机频率的正弦波叠加再归一化。
  单个正弦本身是平缓的，叠加起来既平滑又"随机"；同一个 seed 波形完全可复现。
* 变形本身用的是**平滑二维位移场** `d(x, y)`，不是"沿法线推"：

  ```
  dx = 0.62·sin(2πf·u + φx) + 0.38·sin(2πf·v + φc)
  dy = 0.62·sin(2πf·v + φy) + 0.38·sin(2πf·u + φc)
  ```

  位移是位置的连续函数，所以相邻点位移几乎相同，笔画之间的相对关系不会断裂。
  减去字形中心处的值，整个字不会被平移，基线和字宽保持稳定。
* **幅度安全上限**：取"不同轮廓之间的最小距离 × 0.45"。
  位移最多把任意两点拉近 `2×幅度`，所以只要幅度小于这个上限，
  轮廓之间就不可能相交，映射保持单射 —— **字形有几个洞就还是几个洞**。
  这个上限是必需的：一个 40pt 的 `0`，包围盒 26×41，可笔画只有 2.3pt 宽，
  按包围盒给上限（12pt）足以把洞整个推穿，填充出来就是一团实心块。
  想要更夸张的抖动可以往大调幅度，超了会自动钳住。
* **波数**：横竖方向各走几个噪声周期，默认 2（就是"平缓的波"）。
* **扭曲替换正文**（工具栏复选框，默认勾选）：勾上时先把这一格刷成纸色、
  再画扭曲后的字形，于是屏幕上什么样、纸上/PDF 里就什么样，
  不会"导出后还留着原字体"。取消勾选就变成半透明叠加，方便对照改了哪些笔画。
* **扭曲选中文字的笔画（Ctrl+D）**：给每个字符一个独立的随机种子
  （所以每个字扭曲得都不一样）。
* **换一条噪声波并重新扭曲**：只换波形重新扭，得到另一种抖动。

#### 已经有手写的字：噪声加在**笔迹**上，不换回原字体

Ctrl+D 作用在这几种字上时是这样的（判据在 `distortionEffectKind()`）：

| 这个字现在是什么 | 套扭曲之后 |
| --- | --- |
| 已经铺了手写（Ctrl+H 过的） | **保留手写**，噪声加在手写笔迹上；字符格式里仍然是 `Handwriting` |
| 普通文字 / 随机字体 | 换成"扭曲后的字形"（`Distortion`），老行为不变 |

手写层的抖动同样由工具栏的**噪声幅度 / 波数**决定（幅度是按行高缩放的 0.6 倍，
笔迹是折线、没有"轮廓最小间距"那种硬上限，所以给个保守系数）。
每个字的噪声波按**该字符自己的种子**现生成，所以一个字一个抖法；
「换一条噪声波并重新扭曲」会连手写这些字的种子一起换掉 —— 手写的抖动也跟着变。

> 为什么要有这条规矩：手写是用户一个字一个字采集、一个字一个字校正出来的，
> 套一次扭曲就把它换成机打字，等于把前面的工作全废了。
> "给手写数据加噪声"要的是**抖起来的手写体**，不是"带噪声的印刷体"。
>
> 手写字不归「取消扭曲」（取消扭曲只清 `Distortion`）：它们的抖动是
> 手写层自带的，把「噪声幅度」调到 0 pt 就没有抖动了。

### 2.6 缩放（状态栏右下角 / Ctrl+滚轮）

看版面用的比例尺，**初始 100%**，范围 25%–400%：

* 状态栏**右下角**一条滑块 + 百分比，两边各一个 `−` / `+`（一次 10%）；
  拖滑块是连续的百分比（83% 这种值就是拖出来的）；
* **Ctrl+鼠标滚轮**：在编辑区里直接缩放，一档 ±10%，**以鼠标位置为锚点** ——
  放大时鼠标底下那个字不动。放大镜对着哪儿，哪儿就留在原地；
* **Shift+鼠标滚轮**：横向平移。放大之后纸比窗口宽，右半边就看不着了，
  用它把纸挪过来看（横向滚动条本身是关着的，见下面的取舍）；
* 比例尺**不进文件**：`.tripa` 里不存缩放，重新打开一律 100%
  （排版软件的习惯：比例尺是每个窗口自己的事）。

> 缩放是**视图属性**：只改屏幕上显示多大，排版、分页、打印、导出 PDF、
> 保存出来的 `.tripa` 一个字节都不变（自检里直接断言
> `document()->isModified()` 还是 false）。
>
> 实现上是给"文档坐标 → viewport 坐标"那**一个**变换乘一个倍数
> （`documentToViewport()` 的 m11 = m22 = 缩放），所以正文、光标、选区、
> 手写/扭曲层、鼠标命中测试一起跟着走 —— 不存在"字放大了、点击还按原大小算"
> 这种事（自检里专门验了这一条）。滚动条值仍然是**视图像素**，
> 所以纸宽、居中量、滚动范围都按缩放后的尺寸算。
>
> 一个例外要单独处理：**Qt 自己的自动滚动把"文档像素"和"视口像素"当成一回事**。
> 放大到 200% 时光标在文档里的 y 只要小于视口高度，Qt 就认为"看得见"、一个字都不滚，
> 而屏幕上光标早就跑到纸下面去了。所以键盘事件走完 Qt 那一套之后，
> 再按视图像素补一次 `ensureCaretVisible()`（谁最后设滚动值谁说了算）。
>
> 顺带修掉一个老问题：`QTextEdit::cursorRect()` 返回的是
> **"文档坐标 - 滚动量"**（实测：文档 y=130 的光标，竖滚动 200 之后返回 -70；
> 横滚动 300 时 x 从 0 变成 -300），而画光标时加的那个原点里**已经**含了 -滚动量，
> 于是滚动之后光标被再减一次、直接画到纸外面 —— 表现就是"滚下去以后光标不见了"。
> 现在统一走 `caretRectInDocument()`（把它加回来），自检里用空行文档 +
> 滚动 200 截图量竖条位置来钉住这一条。

### 2.6.1 分页：富文本层不管分页，渲染层按需分页

程序分成两层，界线上只放一样东西 —— **“页”**：

* **富文本层**（`richdocument.*`）：正文、逐字格式（字体 / 颜色 / 手写数据 /
  抖动种子）、每个段落的**字边距和行边距**（字距、行距、段前段后距、缩进、对齐，
  以及“段前分页 / 段中不分页 / 与下段同页 / 孤行控制”这些排版意愿）。
  **它不知道纸有多大，也不知道“页”是什么。**
* **渲染层**（`paginatinglayout.*`）：纸张、页边距、页眉页脚、分页、
  命中测试、光标位置。

为什么要这么分：以前“纸的尺寸”是塞在文档自己身上的
（`document()->setPageSize(正文宽, 纸高)`），于是内容排版和版面几何互相污染，
两个 bug 都是它生的：

* **第二页重复第一页的字**：文档内容是**连续**排下来的，而画的时候是
  “每页把整段文档平移一个纸高、再裁一个正文窗口” —— 每张纸的窗口里装的
  都是文档开头那一段；
* **写着写着出下边界**：越过正文区下边界的字既不会跑到下一页，也不会停下，
  它们落在下边距里被裁掉，屏幕上就是“字写到纸边上就没了”。

现在的模型只有一条地基：**文档坐标就是纸面坐标**。

```
第 p 页的纸面     = [p × 纸高, (p+1) × 纸高) × [0, 纸宽]      （文档坐标）
第 p 页的正文窗口 = 纸面内缩进页边距的那个矩形
```

正文按**行**往正文窗口里填：这一行填不下当前页剩下的高度时，它**整行**搬到
下一页正文窗口的顶部 —— 这就是“按需分页”：

* 页只在这一行真的填不下时才新起一页，**没写到的地方没有页**
  （删掉最后一段，多出来的那页立刻消失）；
* 一行都不会越过正文窗口的下边界（绘制时还按可见页的正文窗口裁一道，
  就算排版算错了也看不见越界）；
* 每一页只有自己那一段内容（各页文字按顺序拼起来正好是全文）。

页眉页脚**默认都不显示**，在页面设置里可以开（`{page}` / `{pages}` / `{title}`）。
它们画在纸的上下边距里，占不到正文窗口，所以开不开都不会让文字重排。

滚动的下边界按“能把最后一页的下边界顶到视窗最上面”定死：

```
视图下边界 = 最后一页的下边界 + 一页高
```

于是滚到底时纸的底边就能停在视窗顶上，再往下那一截就是桌面。

自检分两处：界面这一路是 `--uitest <目录> light pagefix`（40% 下逐页量墨、
往下打字到第 8 页、25%~400% 来回缩放），渲染层本身是单元测试
`build/test_layout.exe`（渲染层本身：按需分页、不越界、不重复、命中/光标往返、
页眉页脚不改排版、段落分页意愿）+ `build/test_jobs.exe`（长活儿与计算层：
分片、进度、取消、按段落惰性算）；还有一个用例是**边打字边量**，
也就是用户写出 bug 的那个用法。

### 2.6.2 长活儿：算的归算、画的归画，进度在状态栏

用户报的是"给文字加噪声这类操作会卡住"。实测数据（`build/bench_effects.exe`）：

| 动作 | 2000 字 | 不处理的话长稿子会是 |
| --- | --- | --- |
| 逐字写效果格式 | 78ms | 2 万字 ≈ 800ms |
| 规划显示表（每帧、而且每帧两遍） | 9.6ms | 2 万字 ≈ 100ms/帧 |
| 算字形几何（取轮廓 + 变形 + 拼路径） | **585ms** | 2 万字 ≈ 6 秒 |

后两项原本都发生在 `paintEvent` 里：点一下"加噪声"，窗口白将近一秒，
而且之后每次滚动都在重算全篇。现在拆成三层：

| 层 | 文件 | 干什么 |
| --- | --- | --- |
| 计算层 | `effectplanner.*` | 把"每个字符该画成什么样"算成显示表：**按段落惰性算**、几何**分片**算 |
| 调度层 | `jobrunner.*` | 长活儿切成 12ms 一片，每片之后让出事件循环；出进度、能取消 |
| 渲染层 | `texteditor.*` | `paintEvent` **只查表 + 落笔**，不做任何几何运算 |

几条写死的规矩：

* **一片要短**（默认 12ms）：任务是在事件循环里被喂的，一片花多久界面就僵多久。
  哪片超了预算会在日志里留一条 `WARN`（`[jobs]`），"卡"这件事从感觉变成数字。
* **进度在状态栏**：任务名立刻显示（一行字不刺眼），**进度条与取消按钮延迟 250ms**
  才出现（短活儿不闪一下）；点 ✕ 或按 **Esc** 取消。
* **取消 = 什么都没发生**：任务停在分片边界、把改过的字符一个个写回去，
  编辑器恢复可编辑，选区也放回原处。
* **计算与渲染解耦**：几何没算好的那一格 **正文照原样画着**（也不会挖洞），
  屏幕上看到的是原字，而不是"原字没了、新字还没来"的空窗。
* **等安静再算**：画完一帧只"登记"要算哪几段，真要排队得等文档安静 150ms ——
  否则打字的人每敲一个字都会触发一次几百个字的几何重算。
* **改文档的任务会临时把编辑器转只读**（几十到几百毫秒），期间滚动、缩放、
  看进度、取消都照常；不这么做的话，"算到一半用户插了一个字"会让位置全部错位。
* **改文档期间压住重画**：任务每改一片文档就变一次，而重画一次就会重新规划
  可见段落、要求重算它们的几何 —— 这是个正反馈。实测：0.4 秒的活跑了 **30 秒**。

顺带的一条使用变化：**没选中文字时，效果操作直接作用于全文**
（以前会弹一个"请先选中一段文字"的模态对话框）。状态栏会明说
"未选中文字，已把噪声波叠加到「全文」N 个字符上"，误操作一次 Ctrl+Z 就能撤。

自检：`build/test_jobs.exe`（分片真的让出事件循环了吗、进度单调吗、取消干净吗、
显示表是不是按段落惰性算的）以及 `tripa.exe --uitest <目录> light progress`
（真点一下"加噪声"：回调必须立刻返回、任务期间事件循环还在转、状态栏真的走到 100%、
干完恢复可编辑、按取消能全撤回、没选区时作用于全文）。

### 2.7 打印与导出
* **文件 → 打印（Ctrl+P）**：标准打印对话框，正文 + 手写 + 扭曲一起输出。
* **文件 → 导出 PDF**：同样的渲染逻辑，方便先看效果。
* 打印时以**打印机实际纸张**为准（可能和页面设置不同），边距沿用页面设置。

> **打印子系统的连接只发生在你按下「打印」之后。**
> 程序启动、打开文件、页面设置、导出 PDF 都不会去连打印机。
> 这一点很关键：Windows 上 `QPrinter` 一被构造出来就会去 `CreateDC`
> 连系统默认打印机，如果默认打印机是网络/WSD 打印机且当前不可达，
> 这个调用会卡住好几秒并弹出系统的「请等待打印机连接或取消连接」。
> 所以：
>
> * 导出 PDF 走 `QPdfWriter`，**完全不碰**打印子系统；
> * `QPrinter` 只在 `printDocument()` 里构造，也就是用户确认打印那一步。
>
> 如果你自己也遇到这个系统弹窗，另一个有效的做法是把
> **Windows 默认打印机改成 `Microsoft Print to PDF` 之类的本地打印机**——
> 打印对话框一打开列的就是它，不会去连接那台网络打印机。

### 2.8 打开 / 保存

* **打开**：`tripa 排版文档 (*.tripa)`、UTF-8 文本（.txt/.md/.csv/.log）或任意文件。
  `.tripa` 走自己的读取路径（把排版和效果一起恢复），其余一律当纯文本读；
  扩展名不认识时还会看文件开头有没有 `<tripaDocument`，所以别人把 `.tripa`
  改名成 `.xml` 也照样能打开。
* **保存（Ctrl+S）**：存过 `.tripa` 就继续存 `.tripa`；`.txt`/`.md` 之类
  一律只写文字本身（和以前一样，见下）。
* **另存为（Ctrl+Shift+S）**：默认就是 **tripa 文档 (\*.tripa)**，
  选「纯文本 (\*.txt)」过滤器则存纯文本。选 tripa 时文件名没写后缀会自动补 `.tripa`。
* 新建 / 打开之前如果文档改过，会先问「是否先保存」（以前打开文件会**直接冲掉**
  未保存的改动，新建才会问）。

> **`.txt` 只装得下文字**：字体、字号、颜色、段落格式、手写层、扭曲层全都在保存时
> 丢掉，重开就是一篇白纸黑字。要连这些都存下来，用 `.tripa`（见 2.9）。

### 2.9 tripa 文档格式（`.tripa`，xml）

`.tripa` 是带排版的文档：**正文 + 逐字格式 + 段落格式 + 页面设置 + 手写/扭曲效果**
全在一个 xml 里，存了再打开，屏幕上和存之前一模一样（包括"同一手写样本、同一条噪声波"
—— 波形是逐分量存下来的，不是按种子重建的）。

```
<?xml version="1.0" encoding="UTF-8"?>
<tripaDocument version="2" generator="tripa" saved="2025-01-01T12:00:00">
    <!-- seed = 全局随机种子：噪声波、逐字效果的种子都从它来 -->
    <effects seed="1234567">
        <handwriting visible="true" replaceText="true" pressureToWidth="0.2"/>
        <distortion visible="true" replaceText="true" amplitudePt="1.6"
                    waveScale="2" lineWidth="0.9"/>
    </effects>
    <page preset="A4" widthMm="210" heightMm="297" orientation="portrait">
        <margins leftMm="20" topMm="20" rightMm="20" bottomMm="20" gutterMm="0"/>
    </page>
    <font family="Microsoft YaHei" pointSize="14"/>
    <wave terms="3">
        <term amplitude="1" frequency="1.37" phase="2.11"/>
        <term amplitude="0.526" frequency="2.72" phase="5.03"/>
        <term amplitude="0.357" frequency="4.08" phase="1.44"/>
    </wave>
    <blocks>
        <block para="0" align="left" indent="0" topMm="0" bottomMm="0"
               leftMm="0" rightMm="0" lineHeight="0" lineType="single"/>
        <block para="1" align="center" indent="2" topMm="9.5" bottomMm="0"
               leftMm="0" rightMm="0" lineHeight="150" lineType="proportional"/>
    </blocks>
    <runs count="2">
        <run start="0" end="3" kind="distortion" seed="1234567"/>
        <run start="6" end="8" kind="handwriting" seed="1234568"/>
    </runs>
    <!-- 正文栏尺寸（pageWidth/pageHeight）就是断行宽度，不存的话重开就乱断行 -->
    <content hash="9f86d081..." chars="19" pageWidth="646" pageHeight="1123">
        <p para="0"><r family="Microsoft YaHei" size="14"><![CDATA[普通文字一段。]]></r>
            <r family="Microsoft YaHei" size="14" weight="700" color="#ffc81e28"><![CDATA[加粗红色]]></r></p>
        <p para="1"><r family="SimSun" size="28" italic="1" underline="single"><![CDATA[换字体的一段]]></r></p>
    </content>
</tripaDocument>
```

各段的意思：

| 元素 | 装什么 | 说明 |
| --- | --- | --- |
| `effects/@seed` | 全局随机种子 | 决定"换一条噪声波"之后的波形与逐字效果种子 |
| `effects/handwriting` `effects/distortion` | 渲染参数 | 两个显示开关、两个「替换正文」开关、幅度 pt、波数、笔宽系数、轮廓线宽 |
| `page` / `margins` | 页面设置 | 预设名、纸张宽高（mm）、纵横、四边距、装订线 |
| `font` | 文档默认字体 | 字体族 + 字号；"没显式设过字体"的字按它排 |
| `wave/term` | 噪声波的分量 | 幅度/频率/相位逐条存；读回来就是**同一条波形** |
| `blocks/block` | 段落格式 | `para` = 段落序号（从 0 起），对齐/缩进/段前段后/行距 |
| `runs/run` | 手写 / 扭曲 / 随机字体 | 按**字符区间**记（`start` 含、`end` 不含），同一效果的连续字符合成一段 |
| `content/p` | 一个段落 | `para` = 段落序号（和 `<blocks>` 对得上）；段内是若干 `<r>` |
| `content/p/r` | 一段同格式文本 | 文本在 CDATA 里**原样**存；格式写成属性（见下表） |

`<r>` 上的字符格式属性（没写的 = 没有那个属性，不是"等于默认值"）：

| 属性 | 对应 | 说明 |
| --- | --- | --- |
| `family` | `FontFamilies` | 多个候选字体用逗号分隔 |
| `size` / `pixelSize` | `FontPointSize` / `FontPixelSize` | 磅值 / 像素值，二选一 |
| `weight` | `FontWeight` | 100–900（`700` = 粗体） |
| `italic` `strikeOut` | `FontItalic` / `FontStrikeOut` | `1` 表示生效 |
| `underline` | `TextUnderlineStyle` | `none/single/dash/dot/dashDot/dashDotDot/wave/spellCheck` |
| `valign` | `TextVerticalAlignment` | `normal/sub/super` |
| `color` / `bg` | 前景 / 背景画刷 | 一律 `#aarrggbb` 八位，半透明也一字不差 |

几个设计上的取舍：

* **正文是纯文本 + 属性，不嵌 HTML**（format version 2 起的改动，也是这次的重点）：
  以前 `content` 里躺着一整份 `QTextDocument::toHtml()` 的 `<html><head><style>…`，
  一个排版工具自己的文档格式里塞一坨 HTML，既不好读也不好改 —— 而且它带来三个坑，
  逼着我们在旁边又另存了三样东西（段落格式、默认字体、栏宽）。现在一个 `<p>`/`<r>`
  就说完的事不再绕道 HTML：文字原样进 CDATA，格式写在属性上。
* **每个 `<r>` 都把字体写全**（连"没显式设过字体"的那些字也按文档默认字体写出来）：
  这样文件是**自足**的 —— 换台机器、换个默认字体打开，排版不会变；
  代价是纯文字的 `<r>` 上也带着 `family`/`size` 两个属性（README 就是宁可选这个）。
* **相邻同格式的片段要合并**：`QTextFragment` 是**按字符**存的（实测 19 个字就是
  19 个 fragment，哪怕格式一模一样），所以扫描时必须自己按"看得见的属性"合并 ——
  否则一次全选改字号会在文件里留下成百上千个 `<r>`。比较时**不能**直接用
  `QTextCharFormat::operator==`：它比的是整张属性表，里面含 Qt 内部的
  `ObjectIndex`（和显示效果无关，同一格式插到不同 fragment 上可能不同），
  拿它比会合并不掉（踩过：6 个字变成 6 个 `<r>`）。
* **段落格式仍然单独存一份 `<blocks>`**：`<p>` 里只放文字和字符格式，
  对齐/缩进/行距/段前段后按**段落序号**记在 `<blocks>` 里，段落序号两边都能对上。
* **效果按字符位置存**，因为手写/扭曲本来就是"一个字符一个效果"，而且它们
  不进 `QTextDocument` 的排版（见 5. 实现要点），正文里根本没有它们的位置。
  位置一旦被改过（有人直接编辑 xml 正文）就会张冠李戴，所以 `content` 上带了
  正文的 **SHA-256**：对不上就**不套效果**，并明确告诉你"效果没恢复，重新应用一次即可"。
* **波形存分量而不是只存种子**：`NoiseWave::reseed()` 用 `QRandomGenerator(seed)`
  生成分量，不同 Qt 版本/平台的浮点结果未必一致；逐分量存下来才能保证
  "同一份文件、同一份字迹"。读不到分量时才退回按种子重建。
* **写入是原子的**（`QSaveFile`）：写一半被打断，磁盘上要么是旧的完整文件、要么是新的。
* **解析一律宽容**：不认识的元素/属性跳过、数值越界钳住、坏的效果区间丢掉，
  缺 `<page>` / `<font>` / `<blocks>` / 波形也照样能读（缺的那些保留调用方当前的值）。
* **老文件照样能打开**：`version="1"` 的 `.tripa` 里 `content` 装的是一段 HTML 的 CDATA，
  读取端认这个老写法（`<p>`/`<r>` 一个都没有时才走 HTML 分支），只是**不再往那个格式里写**。
  存回去就自动升级成 version 2 了。

> **自检到哪一步**：`tests/test_document.cpp`（`test_document.exe`）把
> "文档 → xml → 文档"逐项比对 —— 正文、逐字符格式、段落格式、效果区间、
> 页面设置、渲染参数、波形逐点、**渲染结果逐像素**，再加上一份真写到磁盘再读回来；
> 另有一组专门盯"正文不许是 HTML"（`<p>`/`<r>` 结构、同格式合并、属性正确、
> 文件里不许出现 `<html>` / `qt-*`）。当前 90 项全部通过。

## 3. 手写数据（pattern）格式

和 `getpattern` 的导出**完全一致**：

```
a                       <- 第 1 行：字符标签（这一个文件里的笔画写的是什么字）
560,2030,0.104          <- 之后每行：x,y,pressure
558.6,2030,0.101
                        <- 1 个空行 = 笔画边界（一笔结束）
560,2030,0.066
560,2600,0.066
                        <- 2 个空行 = 字符边界（下一个字开始）
```

约定：

* 标签是**一个**字符 → 文件里所有笔画都属于它；
* 标签是**多个**字符 → 优先用"2 个空行"的字符边界切；边界数对不上就先按几何修
  （丢跨页连线 / 按阅读顺序重排 / 合并或切开），修不好再退回按 x 间隙猜；
* 每一笔正好一个字（标签多字符且笔画数 = 字符数）也直接照收；
* 坐标原点无所谓：加载时会把每个字的包围盒归一化到左上角 (0,0)，
  渲染时**等比缩放到完全塞进字符格子**（宽高取更小的那个比例，
  水平居中、底边压在基线上）—— 保证既不压到邻居，也不会被正文区裁掉；
* **pressure（笔压）就是笔画粗细**：线宽 = 该点 pressure × 当前字号 × 工具栏「笔宽」系数
  （默认 0.20）。所以 0.6 是一笔重墨（字号的 12%），0.1 是起笔的细尖；
  没有第 3 列（老的两列 CSV）时按字高的固定比例画，不会当成"最重的一笔"。
  若某份数据用的是 0~255 之类的原始量纲，程序会按该份数据的最大值自动归一化到 0~1。

`handwrite/` 里的 a–z 是 `tools/make_sample_pattern.py` 生成的示例字母，
保证程序装上就有东西可看。要换成真手写体，直接用自己的 CSV 覆盖或另放目录。

同目录下的 `*.xml` 是可选的**逐字基线/大小校正**（见 2.5 节末尾）：
文件名就是 CSV 名去扩展名，缺了它一切照旧，删掉它等于把所有校正清零。
`<char>` 的属性只有四个：`index`（字符在标签里的下标，0 起）、`label`（纯给人看）、
`baseline`（字身高的比例，正数往下沉）、`size`（缩放倍率，缺省 1.0）。
数值越界会被钳住（baseline ±1、size 0.05~10），xml 坏了就整份忽略并在校对表里报出来。

其它工具：

```powershell
python tools\make_sample_pattern.py   # 重新生成示例字母 CSV
python tools\make_icon.py             # 重新生成程序图标
```

## 5. 实现要点

代码结构（每个文件都不大，方便按需改）：

| 文件 | 作用 |
| --- | --- |
| `mainwindow.*` | 菜单、工具栏、所有动作的编排 |
| `texteditor.*` | **视图层**：编辑区控件（缩放 / 滚动 / 绘制纸张与正文 / 鼠标键盘），坐标变换的唯一出口 |
| `paginatinglayout.*` | **渲染层**：纸张、页边距、页眉页脚 + **按需分页**（一行一行往正文窗口里填，填不下才换页）+ 命中测试 + 光标位置 |
| `richdocument.*` | **富文本层**：正文 + 逐字格式 + 手写/抖动数据 + 每个段落的字/行边距（**不含任何纸、页的概念**） |
| `effectplanner.*` | **效果计算层**：按段落惰性算显示表、分片算字形几何；绘制只读它的结果（见 2.6.2） |
| `jobrunner.*` | **调度层**：长活儿切片、让出事件循环、报进度、支持取消 |
| `effectsrenderer.*` | 手写笔迹与扭曲字形的绘制原语 + 几何计算（算好的交给绘制，见 `prepareEffectItem`） |
| `noise.*` | 平缓噪声波、重采样、平滑、按法线扭曲折线（手写层用） |
| `handwriting.*` | CSV 解析、按间隙切字、归一化、多样本随机取用、逐字基线/大小校正（xml） |
| `effect.*` | 字符级效果（存进 `QTextCharFormat` 的自定义属性） |
| `pagesetup.*` | 页面设置数据结构 + 带预览的对话框 |
| `paragraph.*` | 段落格式（缩进/间距/换行分页/中文版式）+ Word 风格对话框 |
| `fontspool.*` | 随机字体池的选择对话框与持久化 |
| `proofsheet.*` | 手写数据校对表（含缺字清单） |
| `baselineadjust.*` | 逐字基线/大小调整对话框 + 同名 xml 的读写入口 |
| `tripadocument.*` | `.tripa` 文档格式：正文 + 排版 + 效果 + 页面设置 的 xml 读写（见 2.9） |
| `tripa.rc` / `icons/tripa.ico` | Windows 可执行文件自己的图标 + 版本信息（资源管理器 / 快捷方式读的是它，见第 5 节） |
| `main.cpp` | 程序入口 + 统一的分页渲染（PNG/PDF/打印共用）+ 自检入口 |

几个关键取舍：

* **效果不改字符，只改"怎么画"**。手写和扭曲都存在 `QTextCharFormat` 的自定义属性里
  （`EffectKind` + `seed`），文档里始终是原来的字符，因此正则/选中/复制/保存都不受影响。
  想改回普通文字，清掉属性即可（`清除选中文字的全部效果`）。
* **手写/扭曲和正文在同一次绘制里画**（`TextEditor::paintEvent`），不参与
  `QTextDocument` 的排版，所以不会因为"换了字体"而让断行位置乱跳；
  屏幕、`QWidget::grab()`、打印、导出 PDF 走的是同一段代码，真正做到所见即所得。
  早先它是画在一个盖在 viewport 上的**透明子控件**里的，那个做法已经废弃：
  `WA_TranslucentBackground` 会让 Qt 把子控件的区域从父控件的不透明区域里挖掉，
  于是父控件那块干脆不画、子控件的内容又没真正合成上去 ——
  屏幕上看是好的，抓图/打印/导出里却是一个洞（实测覆盖层单独抓图有 2834 个像素，
  合成抓图里一个新墨点都没有）。
* **“页”只存在于渲染层**：富文本层（`richdocument.*`）只管写了什么、每个字什么样子、
  每段多少字距行距；纸有多大、字落在第几页、命中测试给哪个字符，全在
  渲染层（`paginatinglayout.*`）。这条界线是重构的全部意义 —— 以前纸的尺寸
  存在文档自己身上，“内容”和“版面”互相污染，才会长出“第二页重复第一页”
  和“写着写着出下边界”两个 bug（见 2.6.1）。
* **同一个 seed 永远得到同一份样本、同一条波形**，因此重绘、缩放、
  打印都不会让字迹"跳来跳去"；点「换一条噪声波」才会变。
* 字形轮廓由 `QPainterPath::addText()` 取到，自己按容差**自适应细分**曲线
  （Qt6 的 `toSubpathPolygons()` 没有容差参数，内部固定按比较粗的步长细分，
  长笔画会被整段直线化，噪声一叠字形就散了了）。
* **打印子系统是惰性的**：`QPrinter` 只在 `MainWindow::printDocument()` 里构造，
  导出 PDF 用 `QPdfWriter`，`PageSetup::pageSize()` 用"值对象"构造（只查 Qt 静态纸张库）。
  加新功能时请守住这条：任何地方都不要在用户点「打印」之前构造 `QPrinter`
  或查询 `QPrinterInfo`，否则网络打印机不可达时会卡住启动/操作并弹系统连接提示。

### 版面坐标系统的七条铁律

手写/扭曲必须和正文**逐像素重合**，光标/选区要画在对的位置，
鼠标也必须点得准。为此有七个容易踩的坑，都在 `texteditor.*`
和 `effectsrenderer.cpp` 里标注了，改动时别破坏：

1. **文档里不许再出现“纸”：分页全在渲染层。**
   `QTextEdit` 默认的 `LineWrapMode::WidgetWidth` 会**忽略**断行宽度、
   直接按 viewport 宽度断行（纸张居中后 viewport 比正文区宽得多），
   所以 `applyLayoutMetrics()` 仍然要把换行宽度钉在正文宽度上
   （`setLineWrapColumnOrWidth(正文宽)`）—— 但**绝不要再调
   `document()->setPageSize(..., 纸高)`**。

   > 纸的尺寸一旦进文档，“内容”和“版面”就互相污染了：每页都会从文档开头
   > 那一段开始画（第二页重复第一页），越过正文区下边界的字落在下边距里被裁掉
   > （写着写着出下边界）。两个 bug 都是这么来的，见 2.6.1。
   >
   > 版面几何只有一个入口：`RenderMetrics`（纸宽高 + 四个页边距），
   > 由 `TextEditor::applyLayoutMetrics()` 换算出来交给
   > `PaginatingLayout::setMetrics()`；打印 / 导出走的是**同一个接口**，
   > 只是把纸张换成打印机那份，算完再还回去。
2. **纸张居中量只能由"编辑区宽度"算，绝不能读 `viewport()->width()`。**
   居中量是拿去做 `setViewportMargins(pad, 0, 0, 0)` 的，于是
   "边距缩窄 viewport、viewport 宽度又决定居中量"会形成 105/106
   来回震荡的无限递归，直到栈溢出（踩过）。
   `paperPadPx()` 用 `width() - 滚动条预留` 算，与当前状态无关。

   > 注意：这个量**已经体现在 viewport 原点的 x 上**了
   > （viewport 左边缘就是纸张左边缘），所以画纸时不能再加一次。
   > 曾经加过，纸被推右 76 像素，光标就再也落不到纸面上。
   >
   > 同一个"view 尺寸 ↔ 版面"的环还有第二种表现（2026-10 抓到）：
   > **竖滚动条按需显隐**会让 viewport 宽度在 1110/1096 之间跳，
   > 每跳一次都触发重排 + 滚动范围重算。所以竖滚动条改成**常驻**
   > （`ScrollBarAlwaysOn`），并且所有"改版面"的信号都排到下一轮
   > （`scheduleLayoutUpdate()`）。这两条缺一不可 ——
   > 日志里那个"一秒 3704 次"的活锁就是它，完整过程见 1. 节末尾。

3. **只有两个坐标空间，别自己造第三个。**

   | 空间 | 原点 | 值域来源 |
   |---|---|---|
   | 文档坐标 | **第一页纸的左上角**（就是纸面坐标） | `documentLayout()->blockBoundingRect()`、`PaginatingLayout::lineRect()`、`caretRectInDocument()` |
   | viewport 局部坐标 | viewport 左上角 | `documentToViewport()`、`QMouseEvent::pos()`、`QPainter(viewport())` |

   换算只有一条：`viewport 局部坐标 = 文档坐标 × 缩放 + 纸面原点`，
   也就是 `TextEditor::documentToViewport()`；反过来是它的 `.inverted()`。
   缩放（2.6）就是**乘在这一个变换上的倍数**，不另开坐标空间：
   `QTransform(zoom, 0, 0, zoom, dx, dy)` 一行写死，比 `translate()`/`scale()`
   连写更不容易搞错顺序。缩放变了要一起改的只有"跟视图像素有关的那几样"：
   纸张尺寸、居中量、滚动范围、光标矩形，全在 `applyZoom()` 一处收口。

   > `QTextEdit::cursorRect()` **不属于**上面这两个空间：它给的是
   > "文档坐标 - 滚动量"。滚动量为 0 时和文档坐标一模一样，
   > 所以这个坑只在滚动之后才现形（画出来的光标少算一个滚动量、直接消失）。
   > 要文档坐标就加回滚动量，统一走 `caretRectInDocument()`。

   > 这里曾经有个**接口和实现差一层**的坑：`documentToViewport()` 的值域明明是
   > viewport 局部坐标，可 `documentCursorAt()` 的参数被写成"排版坐标"
   > （= 局部坐标 + viewport 在编辑区里的偏移），于是调用方按名字多减了一次原点，
   > 命中测试整段偏一个"纸张居中量 + 工具栏高度"，每次点击都落到纸外面。
   > 现在 `documentCursorAt(const QPoint &viewportPos)` 的签名直接写死
   > "就是 `QMouseEvent::pos()` 那一套"，`viewportToEditor()` 只留给
   > 需要窗口坐标的自检用。

4. **正文、光标、选区、效果层必须共用同一个原点变换**，也就是
   `TextEditor::documentToViewport()`。任何一边自己 `translate`
   都会让笔迹或光标整体偏一个页边距。

5. **鼠标进来只认一套坐标：`event->pos()`。**
   三个鼠标事件全部重写（`QTextEdit::cursorForPosition()` 内部按自己那套换算，
   viewport 边距、行高取法和这里都不一样，和正文实际画的位置差一个页边距），
   统一走 `documentCursorAt(event->pos())`。
   自检驱动这三个入口时也**只送 viewport 局部坐标** ——
   自检里两套坐标约定并存过，结果靶点是局部坐标、事件却按排版坐标处理，
   点击整段偏移；而且这种偏移很难被测出来：断言只看"点中哪一行"，
   光标贴到下一行时行号照样对，只有列会悄悄变成行尾。

   > **拖选的锚点必须在按下时记下来**（`m_dragAnchor`），
   > 不能在 `mouseMoveEvent` 里读 `textCursor().anchor()` ——
   > 那个值每扩一次选区就被推到上一次的终点上：
   > 往左拖会变成"行首..按下点"（终点永远贴着一行的开头），
   > 往右拖会塌成一个点。用户报的"起点和终点一定在一行的开始或末尾、
   > 不能选到中间就停"就是往左拖的那种。

6. **`QPainterPath::addText()` 的坐标：y 向下、基线在原点、单位是磅。**
   一个 18pt 的 `l` 轮廓是 `(x, 0) .. (x, 15.2)`，`0` 就是基线。
   所以：不要乘 1/64 的"定点转换"（整体缩小 64 倍），
   也不要再翻一次 y（字会上下颠倒、还会被挪到基线下面去）。
   这两件事以前都干过，`--uitest` 里的 `uitest_outline_orient.png`
   就是专门用来核对这一条的（`L`/`F` 上下不对称，被镜像了一眼就能看出）。

7. **求"这个字用什么字体"不能用 `QTextCharFormat::font()`。**
   它只返回格式里**显式设过**的属性，没设的字号会落到 `QFont` 的默认值
   （→ QApplication 的默认字号），而**不是**文档的默认字体。
   文档里只有一部分字显式设过字号时（"整篇 28pt、其中几个字被单独改过"），
   拿它算出来的"行高 / 自然字高"比例会差一倍，笔迹要么缩成一半、要么涨成两倍。
   统一走 `effectiveFont()`（默认字体 → 块格式 → 片段格式逐层 `resolve`）。

### 效果层怎么"替换"原字（不要刷底色）

"变形后的文字有个白底、把选框挡住，只留约 1 像素蓝边"是刷底色刷出来的：
效果层如果靠往纸面上铺一块纸色来盖原字，而效果层又画在正文（含选区高亮）之上，
那块底色就会连选区一起盖掉。

正解是**别盖，让正文这一格根本不画**（`TextEditor::paintEvent`）：
1. **计算层**（`effectplanner.*`）先算出"每个字符该画什么"，
   顺便标出"哪些格子会被整格替换掉"（`EffectDrawItem::hidden`）；
2. 用这些格子做"正文窗口 - 一堆洞"的裁剪，再画正文 —— 原字被挖掉，纸面保持干净；
3. 同一遍绘制里再画变形后的字形（`renderPreparedEffects`）；
   打印和导出（`tripaRenderToDevice`）用同一份计划，屏幕上什么样纸上就什么样。
配套的几个坑：

* **选区高亮要单独画一遍、而且不带那套裁剪。** 挖的洞就是选区高亮要画的那些格子，
  两件事合成一遍的话高亮会连同原字一起被挖掉：选中变形后的文字时底下的蓝底没了、
  变形层又是深蓝墨，看着就像"选区被盖住了"（实测选区色像素从 8400 掉到 1084）。
  所以第一遍不裁剪、只铺背景色（前景设成透明），第二遍才带裁剪画正文。
* **画效果层之前必须把裁剪去掉**（`setClipping(false)`）：洞的位置正是效果层要画的地方，
  带着裁剪画等于把新字形也一起裁掉，屏幕上只剩一片空白。
* **挖洞的裁剪要用 `QRegion`，不能用 `QPainterPath`**：每页几百个格子当洞
  加进一个奇偶规则的路径里，光是把它变成裁剪区就要好几秒，而且格子越多越慢
  （实测一帧 469ms -> 3261ms -> 8176ms）。`QRegion` 是**按行合并**的：
  一整行里相邻的格子会并成一个矩形，几百个洞最后只剩几十个矩形。
* **几何没算好的格子不挖洞**：那种格子正文照原样画着（屏幕上不会出现
  "原字没了、新字还没来"的空窗），算好了才一起换成变形字形，见 2.6.2。
* **不能用 `QTextLayout::setFormats()` 设透明前景来隐藏原字**：它会 invalidate 布局，
  而布局一失效，任何**之前**拿到的 `QTextLine` / `blockBoundingRect` 都成了悬垂引用，
  别处再调 `line.y()` 就直接段错误（实测就是这么崩的，崩在 `QTextLine::y()` 里）。
  同理，自检里 `QTextLine` 要用的那一刻才现取，取完只留数值。

### 光标和选区为什么要自己画

`TextEditor` 的 `paintEvent` 是自己写的（要画纸张、页边距、居中），
于是绕开了 `QTextEdit` / `QWidgetTextControl` 里那两条默认通路：

* **光标**：`PaintContext::cursorPosition` 默认是 `-1`（= 不画），
  而"此刻该不该显示"（闪烁相位）是 `QWidgetTextControl` 的私有状态，
  外人拿不到。所以光标由 `drawCaret()` 自己画：
  位置取 `QTextEdit::cursorRect()`（**文档坐标**）+ `documentOriginInViewport()`，
  闪烁沿用 Qt 自带定时器的相位（它在暗相位会把 `cursorRect()` 置空）。
* **选区**：默认是在 `QWidgetTextControl::drawContents()` 里把选区塞进
  `PaintContext::selections` 的。这里没走那条路，所以要自己填
  `context.selections`，颜色取调色板里的 `Highlight` / `HighlightedText`
  （深色主题默认给的浅色前景落到白纸上就等于隐形）。
* **鼠标**：`QTextEdit::cursorForPosition()` 内部按自己那套换算
  （viewport 边距、行高取法都和这里不一样），和正文实际画的位置差一个页边距。
  三个鼠标事件都重写了，统一走 `documentCursorAt()`，
  拖选锚点存在 `m_dragAnchor`（见铁律 5）。

### 自检怎么量"对齐"

`--uitest <目录> dark|light probe` 不只是截图，它会：

* 强制一套深色/浅色调色板，断言**纸面是白的、字是深色的**
  （深色主题曾经把纸张涂成灰色、文字看不见）；
* **光标**：在**空文档**下截图（此时画面上除了光标什么都没有，
  不用再猜"这团墨迹是字母还是光标"——`I`、`H` 的竖笔也是整行高），
  量出竖条的位置，断言它与 `documentOriginInViewport() + cursorRect()`
  的偏差在 3 像素内，而且落在纸面里（跑到灰桌面上就是"看不见"）；
* **选区**：全选后断言高亮左边缘 = 正文左边缘、右边缘不超出纸张
  （颜色只认钉死的 `#3399ff`，否则窗口描边、面板拖柄会被算进来）；
* **鼠标定位**：在第 0/1/2 行各点一下，断言光标确实落在那一行；
* **精确拖选**：从第 0 个字拖到第 5 个字，断言锚点和终点都等于"按下点/松手点
  的命中结果"（只断言行号不够 —— "框选不到想要的位置"恰恰是列的问题）；
* **连续拖选**：按下之后分 4/6/8/10 步连续移动，左拖和右拖都测，
  断言锚点没被上一帧的终点顶掉、终点就是松手点、两头都在**行中间**
  （只送一次移动会绕过这个 bug —— 起点贴行首时那一次移动照样"看起来对"）；
* **Shift+方向键**：扩选 4 次，断言选中 `HAND` 且画面上真有高亮像素
  （用户报过"Shift 扩选有效但看不到提示"）；
* **扭曲替换的"透明底"**：只量正文第一行那一横条，断言
  ①开效果后原来的黑墨基本消失（原字真被裁掉了，不是被底色盖的）、
  ②那里出现了约两千个扭曲色的墨（新字形真的画出来了）、
  ③全选之后选区色像素不减少（没有底色在啃选框）；
* **多块文档**：两行文档，只给第 2 行套扭曲，断言第 1 行的墨一个不少、
  第 2 行的黑墨换成了扭曲墨（逐块挖洞时块的位置一旦算错，第 2 块起会整体叠到第 1 块上，
  只测单行文档看不出来）；
* **效果层对齐**：把正文和效果层各画一遍到同尺寸画布，
  比较两者墨迹的包围盒，超阈值就报错退出；
  同时按行高分段统计墨迹，区分"整体平移"和"某几行被缩放"；
* **字形拓扑**：对 `0 4 扭 H g 回 %` 断言变形前后**每条轮廓的绕向不变**
  —— 有符号面积一旦翻号，"洞"就会被填实（`0` 变实心椭圆）；
* 输出几张给人看的对照图：`uitest_cursor_zoom.png`（光标附近放大）、
  `uitest_glyph_compare.png`（原字形 vs 扭曲后）、
  `uitest_align_check.png`（正文与扭曲字形共基线）、
  `uitest_distort_off.png` / `uitest_distort_bg.png`（关/开效果的对照）、
  `uitest_distort_sel.png`（选中变形后的文字：蓝底 + 变形笔画）。
  > 断言要盯的是**像素**，不是"文字看起来像"。上面几条效果层断言全都栽过跟头：
  > 一次是"只数深色像素"把桌面底色 `#3a3d42` 也算成墨；
  > 一次是拿来比的图根本不是"关效果"那张，于是"新墨 0 个"报了假警。

> 量测的坑（两个，都是拿"读起来对"的写法踩出来的）：
>
> * `QWidget::grab()` 对**子控件**是把控件画在**父控件坐标系**里再截的，
>   不是控件局部坐标。曾经拿 viewport 的 grab 当"viewport 内的位置"用，
>   整段测量凭空平移了一个纸张居中量，于是得出了错的结论。
>   现在统一在**窗口坐标**里量，并且扫描范围卡在纸面以内
>   （紧挨着纸右边的竖滚动条是整条深色，扫进去会把包围盒拉歪）。
> * `window.grab()` 在**改了状态之后**不可靠：它拿的是子控件**当前后备存储**里的
>   内容，而 `QApplication::processEvents()` 并不保证绘制已经发生 ——
>   于是"滚动到第 2 页之后截的图"其实还是滚动之前那一帧
>   （实测：纸是新的、纸上的字和光标还是旧的，查了半天"正文没跟着纸走"）。
>   要量**编辑区**里的东西（纸、正文、光标、效果层），一律用
>   `editor->viewport()->grab()`，并且在改动状态之后先 `viewport()->repaint()`
>   强制一次同步绘制（`--uitest` 里的 `settle()` 就是干这个的）。

### 程序图标为什么要嵌进 exe

`QApplication::setWindowIcon()`（`main.cpp`）只管**窗口左上角、任务栏、Alt+Tab 列表**。
**资源管理器里的文件图标、文件属性的"图标"、快捷方式默认取的图标，读的是 exe 自己的
`RT_GROUP_ICON` 资源** —— 那是链接器写进去的，Qt 运行时一点忙都帮不上。
所以只设 `setWindowIcon` 的话，exe 在资源管理器里就是一个白板默认图标。

于是有两份图标、两条路：

| 文件 | 谁用 | 怎么进去 |
| --- | --- | --- |
| `icons/tripa.png` | Qt 运行时（窗口、任务栏） | `resources.qrc` → `:/icons/tripa.png` |
| `icons/tripa.ico` | Windows（资源管理器、快捷方式） | `tripa.rc` → windres/rc 编成对象一起链接 |

`icons/tripa.ico` 是**多尺寸**的（16/24/32/48/64/128/256，每档一张 PNG，
`tools/make_icon.py` 里按面积平均缩小生成）—— 只放一张 256 的话，
小图标视图下会被资源管理器糊成一团。`tripa.rc` 里那条 `ICON` 写的是
**相对 `.rc` 文件所在目录**的路径（`icons\tripa.ico`），windres 是按自己的
当前目录找的，所以手工构建时要先 `cd` 到仓库根（见 `tools/build-manual.ps1`）。

## 6. 已知限制

* **`.txt` 只存文字**：字体、颜色、段落格式、手写/扭曲都不落盘，重开就是白纸黑字。
  要连排版一起存就用 `.tripa`（见 2.9）。
* `.tripa` 里**不存手写 CSV 本身**（那是采集数据，动辄几 MB），只存"哪些字符用了手写
  效果"。换台机器打开时只要那个字符在自己的手写库里、或者干脆没载入数据，
  效果层就会显示成缺数据（状态栏/校对表会告诉你缺哪些字），正文和排版不受影响。
* 手写效果的落点是"按字符格等比缩放"，不记录**具体用了哪一份样本**（同字符多份样本时
  按种子随机取用）。存了种子，所以同一次会话里重绘、打印都不会跳；
  但换一份手写数据、或者 Qt 的随机数实现变了，可能会挑到另一份样本。
* 内置示例手写数据只有 a–z（几何字母造型，不是真人笔迹）；
  中文、数字、标点需要自己采（校对表会告诉你缺哪些）。
* 精确的一键"选中所有"在 Qt 里做不了：`QTextCursor` 只支持一段连续选区。
  所以这里取"最长连续同类块 + 黄色高亮其余匹配"，并且让效果操作作用于全部匹配。
* 手写层与扭曲层是"覆盖绘制"，不改变文档排版；
  如果希望手写字**参与排版**（按笔迹宽度重新断行），需要把手写做成真正的 QFont，
  那是另一条路线（可以再谈）。
* **缩放在 `.tripa` 里不保存**（有意为之，不是漏存）：比例尺是视图属性，
  换台机器、换个屏幕打开同一个文件，看到多少 DPI 是不确定的，
  存一个"上次是 83%"反而会让下次打开莫名其妙地不是 100%（见 2.6）。
* 缩放只改**显示**：Qt 自己的自动滚动按"文档像素 = 视口像素"算，
  所以键盘走完之后要再补一次按视图像素的滚动（`ensureCaretVisible()`）。
  拖选到窗口外时的自动滚动仍然没有（那是另一个功能，本来就没做）。
* **横向滚动条是关着的，竖向滚动条是常驻的**：
  横向平移只有 Shift+滚轮 / 触控板的横向滚动（值我们用，条子不显示：
  让它可见的话 Qt 会按"文档宽度"接管横向范围，而我们按"纸张宽度"设，
  两者不一样）。放大到纸比窗口宽时靠 Shift+滚轮挪。
  竖向**必须常驻**（`ScrollBarAlwaysOn`）—— 见下面那条活锁，这是它的正解。
* **版面的回调一律排到事件循环的下一轮**（`scheduleLayoutUpdate()`）。
  `updateScrollRange()` 会改 viewport 边距，而 viewport 尺寸一变就会重排、
  重排又发 `documentSizeChanged`：直接相连就是个自激环。踩到过一次
  ——**一秒 3704 次调用、界面彻底卡死**，而且因为竖滚动条反复显隐
  （宽度在 1110 <-> 1096 之间跳），环在两处互相喂。两处都修了之后，
  自检 soak 组 400 轮里同一指标降到正常操作的几十次/秒。
* **分页是按行填满才换页**（“按需分页”），没有单独的“插入分页符”
  命令：想从新的一页开始，用段落的**段前分页**（段落对话框 → 换行和分页）；
  “段中不分页 / 与下段同页 / 孤行控制”也在那里，由渲染层在分页时兜住。
  页与页之间在屏幕上就是一张张纸，中间那道空白是**纸的上下边距 + 桌面**，
  不是“文档里的空行”（这点和 Word 的草稿视图不一样）。
* **`window.grab()` 抓不到刚改过的子控件状态**（见第 5 节末尾那段说明）。
  自己的截图/量测代码要点：改完状态先 `viewport()->repaint()`，
  或者干脆别 grab 窗口、直接 grab viewport。
* **一个 CSV 一整页字**（`train/handwrite*.csv` 那种）时，第 1 行的标签是**识别结果**：
  只要识别结果和实际写的字在某个位置差了一个（识别漏字、多认一个字、你手动改过标签），
  从那里往后的槽位就会整体错位一格 —— 校对表和基线调整对话框的预览都能看出来
  （"字"列写的是漏、预览里的笔迹却是另一个字），但程序无从判断谁对谁错。
  想彻底避免：一个字一个 CSV，或者保证标签与书写顺序严格一致。
  另外带下伸部的西文字母（g/y/p/q/j）默认会略微偏高，
  用「调整手写基线 / 大小…」逐字下移即可（自动对齐也能一次搞定）。
* **效果几何是"边看边算"的**：套上效果之后，看得见的那几页先算（几毫秒到
  几百毫秒，取决于字号和字数），屏幕上的字会**逐个**从原字变成扭曲字形/手写笔迹。
  这是故意的：算几何很贵（实测 2000 字 585ms），放在绘制路径里就是"点一下白一秒"。
  没算好的格子显示的是原字（不是空白），状态栏会告诉你还剩多少个字。
  快速滚动到没算过的一页时，那一页会这样"填"一遍。
* **没选中文字时，效果操作作用于全文**（不是弹窗要你选）。
  状态栏会明说"作用于「全文」N 个字符"；想只改一段就先选中它。
  一次 Ctrl+Z 能把整个操作（哪怕分了几百片）全部撤回去。
